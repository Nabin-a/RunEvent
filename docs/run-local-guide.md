# คู่มือรัน Kratai บนเครื่องตัวเอง (สำหรับมือใหม่)

คู่มือนี้พาเปิดระบบ Kratai บนคอมพิวเตอร์ของคุณเองทีละขั้น ตั้งแต่ติดตั้งโปรแกรมจนเปิดหน้าเว็บได้ ถ้าทำตามครบ ใช้เวลาประมาณ 10–15 นาที (ส่วนใหญ่คือรอดาวน์โหลด)

> ข้อมูลทั้งหมดในระบบนี้เป็น **ข้อมูลจำลอง** ไม่มีการตัดเงินจริง ไม่มีการล็อกอิน Google/LINE จริง ลองกดอะไรก็ได้ไม่ต้องกลัวพัง

---

## 1. ทำความรู้จักโปรเจกต์ก่อน (อ่าน 1 นาที)

Kratai แบ่งเป็น 2 ส่วนที่ต้องทำงานพร้อมกัน:

| ส่วน | หน้าที่ | ทำงานที่ |
|---|---|---|
| **หน้าเว็บ (Frontend)** | หน้าตาที่เราเห็นและกดได้ ทำด้วย React + Vite | `http://localhost:5173` |
| **ระบบหลังบ้าน (Backend / API)** | รับคำสั่งจากหน้าเว็บ เช่น สมัครวิ่ง ล็อกอิน แล้วบันทึกลงฐานข้อมูล ทำด้วย Node.js + Express | `http://localhost:3001` |

- **ฐานข้อมูล** เป็นไฟล์เดียวชื่อ `data/kratai.sqlite` (SQLite) ไม่ต้องติดตั้งโปรแกรมฐานข้อมูลแยก
- คำว่า **localhost** แปลว่า "เครื่องของเราเอง" คนอื่นในเน็ตเปิดไม่ได้
- ตัวเลขหลัง `:` เช่น `5173` เรียกว่า **พอร์ต (port)** เหมือนเลขห้องในตึกเดียวกัน แต่ละโปรแกรมใช้ห้องของตัวเอง

คำสั่งเดียว `npm run dev` จะเปิดทั้ง 2 ส่วนให้พร้อมกัน (ดูขั้นที่ 4)

---

## 2. ติดตั้งโปรแกรมที่ต้องมี (ทำครั้งเดียว)

### 2.1 Node.js — เวอร์ชัน 22.13 ขึ้นไป (แนะนำ 22 LTS หรือ 24)

Node.js คือโปรแกรมที่ทำให้รันโค้ด JavaScript/TypeScript นอกเบราว์เซอร์ได้ และมาพร้อม **npm** (ตัวติดตั้งไลบรารี)

1. เข้า <https://nodejs.org> แล้วดาวน์โหลดตัว **LTS**
2. ติดตั้งแบบกด Next ไปเรื่อย ๆ ได้เลย
3. เปิด **Terminal** ใหม่ (Windows ใช้ PowerShell หรือ Git Bash, macOS ใช้ Terminal) แล้วพิมพ์:

```bash
node -v
```

```bash
npm -v
```

ถ้าขึ้นเลขเวอร์ชัน เช่น `v24.18.0` และ `11.16.0` แปลว่าติดตั้งสำเร็จ

> **ทำไมต้อง 22.13 ขึ้นไป?** ระบบหลังบ้านใช้ฐานข้อมูล `node:sqlite` ที่มีมาในตัว Node.js รุ่นใหม่เท่านั้น ถ้าใช้รุ่นเก่ากว่าจะเจอ error ตอนเปิด API (ดูข้อ 7)

### 2.2 Git (ถ้ายังไม่มีโค้ดในเครื่อง)

ใช้ดาวน์โหลดโค้ดจาก GitHub — <https://git-scm.com> ติดตั้งแบบค่าเริ่มต้นได้เลย ถ้าได้โฟลเดอร์โปรเจกต์มาแล้ว (เช่น copy มาจากเพื่อน) ข้ามข้อนี้ได้

## 3. เตรียมโค้ด (ทำครั้งแรกครั้งเดียว)

### 3.1 เข้าไปในโฟลเดอร์โปรเจกต์

ใน Terminal ใช้คำสั่ง `cd` (change directory = ย้ายโฟลเดอร์) ไปยังโฟลเดอร์ที่มีไฟล์ `package.json` อยู่ เช่น:

```bash
cd path/to/RunEvent
```

เช็กว่าอยู่ถูกที่ด้วยการพิมพ์ `ls` (หรือ `dir` บน PowerShell) ต้องเห็นไฟล์ `package.json`, โฟลเดอร์ `src` และ `server`

### 3.2 ติดตั้งไลบรารีที่โปรเจกต์ใช้

```bash
npm install
```

- คำสั่งนี้อ่านรายชื่อไลบรารีจาก `package.json` แล้วดาวน์โหลดมาเก็บในโฟลเดอร์ `node_modules`
- ใช้เวลา 1–3 นาที ขึ้นกับเน็ต
- มีข้อความ `warn` สีเหลืองไม่เป็นไร ถ้าจบด้วย `added ... packages` ถือว่าสำเร็จ
- ทำแค่ครั้งแรก หรือทำใหม่เมื่อมีคนเพิ่มไลบรารี (ไฟล์ `package.json` เปลี่ยน)

## 4. เปิดระบบ (ทำทุกครั้งที่จะใช้งาน)

```bash
npm run dev
```

รอจนเห็นข้อความประมาณนี้ใน Terminal:

```text
[api] [Kratai API] SQLite server listening on http://127.0.0.1:3001 (DB: .../data/kratai.sqlite)
[web]   VITE v6.x  ready in 1300 ms
[web]   ➜  Local:   http://localhost:5173/
```

- `[api]` = ระบบหลังบ้าน, `[web]` = หน้าเว็บ ขึ้นทั้งคู่แปลว่าพร้อม
- **เปิดเบราว์เซอร์ไปที่ <http://localhost:5173>**
- รันครั้งแรก ระบบจะสร้างไฟล์ฐานข้อมูลพร้อมข้อมูลตัวอย่าง (งานวิ่ง ผู้ใช้ทดสอบ) ให้อัตโนมัติ
- **อย่าปิดหน้าต่าง Terminal นี้** ระหว่างใช้งาน ถ้าปิด เว็บจะหยุดทำงาน

### หยุดระบบ

คลิกที่หน้าต่าง Terminal แล้วกด **`Ctrl + C`** (macOS ก็ใช้ `Ctrl + C`) ถ้ามีคำถาม `Terminate batch job (Y/N)?` ให้พิมพ์ `Y` แล้ว Enter

### แก้โค้ดแล้วต้องรีสตาร์ตไหม?

ไม่ต้อง ระบบมี **hot reload**:
- แก้ไฟล์ใน `src/` (หน้าเว็บ) → หน้าเว็บอัปเดตเองภายในวินาที
- แก้ไฟล์ใน `server/` (หลังบ้าน) → API รีสตาร์ตตัวเองอัตโนมัติ

## 5. ลองใช้งาน: สลับบัญชีทดสอบ

ตอนเข้าเว็บครั้งแรกจะเป็น **ผู้เยี่ยมชม (Guest)** ยังไม่ล็อกอิน

**วิธีที่ง่ายที่สุด:** กดปุ่มลอย **Dev / Demo** มุมล่างขวาของหน้าเว็บ แล้วเลือกบทบาทที่อยากลอง เช่น นักวิ่ง เจ้าขององค์กร ฝ่ายการเงิน เจ้าหน้าที่รับอุปกรณ์ ระบบจะสลับให้ทันทีโดยไม่ต้องพิมพ์รหัสผ่าน

**ถ้าอยากลองล็อกอินผ่านฟอร์มจริง:** ใช้บัญชีนักวิ่งตัวอย่าง (เป็นข้อมูลสมมติ อยู่ในไฟล์ seed ของโปรเจกต์)

| อีเมล | รหัสผ่าน |
|---|---|
| `kanpitcha.runner@demo.kratai.local` | `demo1234` |

บัญชีทดสอบอื่น ๆ ดูได้ใน `src/data/mockData.ts`

---

### 5.1 แสดงความคิดเห็นระหว่างทดสอบ (เหมือน comment ใน Google Docs)

1. กดปุ่ม **ปักหมุด comment** มุมล่างขวา (เหนือปุ่ม Dev / Demo) เคอร์เซอร์จะเป็นเป้า
2. คลิกจุดที่อยากติ แล้วพิมพ์ความคิดเห็น → **ส่งความคิดเห็น** (หรือ `Ctrl + Enter`)
3. หมุดตัวเลขจะเกาะอยู่กับจุดนั้น กดหมุดเพื่อ **ตอบกลับ** หรือกด **แก้แล้ว** เมื่อแก้เสร็จ
4. ปุ่มตัวเลขข้าง ๆ เปิด **รายการความคิดเห็นทั้งหมด** กดรายการเพื่อพาไปหน้านั้นและเปิดหมุดให้

- ความคิดเห็นเก็บในฐานข้อมูลของเซิร์ฟเวอร์ ทุกคนที่ใช้เซิร์ฟเวอร์เดียวกัน (เช่น VM ของทีม) เห็นชุดเดียวกัน
- ปุ่ม "รีเซ็ตข้อมูลจำลอง" **ไม่ลบ** ความคิดเห็น
- ฟีเจอร์นี้มีเฉพาะตอนเปิดเครื่องมือทดสอบ (sandbox) ระบบจริงจะไม่แสดง

## 6. ล้างข้อมูลกลับเป็นค่าเริ่มต้น

ลองสมัคร/แก้ข้อมูลไปเยอะแล้วอยากเริ่มใหม่ เลือกทางใดทางหนึ่ง:

- **ทางง่าย:** กดปุ่ม **Dev / Demo** → **รีเซ็ตข้อมูลจำลองเริ่มต้นทั้งหมด**
- **ทางล้างหมดจด:** หยุดระบบ (`Ctrl + C`) → ลบไฟล์ `data/kratai.sqlite` → `npm run dev` ใหม่ ระบบจะสร้างฐานข้อมูลตัวอย่างให้ใหม่

> ไฟล์ใน `data/` เป็นข้อมูลบนเครื่องคุณคนเดียว ลบได้ไม่กระทบคนอื่น

## 7. เจอปัญหา ทำยังไงดี

| อาการ / ข้อความ error | สาเหตุ | วิธีแก้ |
|---|---|---|
| `'node' is not recognized` หรือ `command not found: npm` | ยังไม่ได้ติดตั้ง Node.js หรือยังไม่ได้เปิด Terminal ใหม่หลังติดตั้ง | ติดตั้งตามข้อ 2.1 แล้ว **ปิด-เปิด Terminal ใหม่** |
| `No such built-in module: node:sqlite` หรือ `ERR_UNKNOWN_BUILTIN_MODULE` | Node.js เก่าเกินไป | อัปเดต Node.js เป็น 22.13 ขึ้นไป แล้วเช็กด้วย `node -v` |
| `npm ERR! enoent ... package.json` | อยู่ผิดโฟลเดอร์ | `cd` ไปโฟลเดอร์ที่มี `package.json` (ข้อ 3.1) |
| `Cannot find module ...` หรือ `vite: not found` | ยังไม่ได้ติดตั้งไลบรารี | รัน `npm install` |
| `EADDRINUSE ... :3001` | มีโปรแกรมอื่น (หรือ Kratai อีกหน้าต่าง) ใช้พอร์ต 3001 อยู่ | ปิด Terminal เก่าที่รันค้างไว้ หรือรีสตาร์ตเครื่อง |
| `Port 5173 is in use, trying another one...` | พอร์ตหน้าเว็บถูกใช้อยู่ ระบบเลยย้ายไปพอร์ตถัดไปเอง | เปิดตามลิงก์ในบรรทัด `Local:` (เช่น `http://localhost:5174`) หรือปิด Terminal เก่าที่รันค้างไว้แล้วรันใหม่ |
| เว็บเปิดได้แต่ข้อมูลไม่ขึ้น / ขึ้น error การเชื่อมต่อ | ฝั่ง `[api]` ไม่ได้ทำงาน | ดูใน Terminal ว่ามีบรรทัด `[api]` สีแดงไหม อ่าน error แล้วเทียบกับตารางนี้ |
| หน้าเว็บค้างข้อมูลเก่าแปลก ๆ | ข้อมูลทดสอบเพี้ยน | รีเซ็ตตามข้อ 6 |

ยังแก้ไม่ได้: copy ข้อความ error **ทั้งก้อน** จาก Terminal ส่งให้ทีม พร้อมบอกว่าพิมพ์คำสั่งอะไรไป และผลของ `node -v`

## 8. คำสั่งอื่นที่ควรรู้

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm run dev` | เปิดทั้งหน้าเว็บและหลังบ้าน (ใช้บ่อยที่สุด) |
| `npm run dev:web` | เปิดเฉพาะหน้าเว็บ (หลังบ้านจะไม่ทำงาน ข้อมูลจะไม่ขึ้น) |
| `npm run dev:api` | เปิดเฉพาะหลังบ้าน |
| `npm run typecheck` | ตรวจว่าโค้ด TypeScript ไม่มีจุดผิดชนิดข้อมูล ควรผ่านก่อนส่งงาน |
| `npm run build` | ลองสร้างไฟล์สำหรับขึ้นเซิร์ฟเวอร์จริง (ผลอยู่ในโฟลเดอร์ `dist/`) ควรผ่านก่อนส่งงาน |

> สคริปต์ช่วยรันอัตโนมัติ (ตรวจ Node → `npm install` ถ้าจำเป็น → เปิดระบบ) อยู่ใน `.agents/skills/run-local/scripts/` สำหรับคนที่อยากใช้คำสั่งเดียวจบ ดูรายละเอียดใน [README.md](../README.md#วิธีรันโปรเจกต์ต้นแบบบน-local)
