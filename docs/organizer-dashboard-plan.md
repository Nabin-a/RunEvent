# แผน Dashboard ผู้จัดงาน RunEvent

วันที่: 16 พฤศจิกายน 2026
ปรับปรุงล่าสุด: 17 พฤศจิกายน 2026 — เพิ่มแผนร้านค้า การโปรโมท และจัดซื้อ/ผลิต โดยยังไม่ออกแบบภาพหรือพัฒนา
สถานะ: ข้อเสนอเพื่อทบทวน ยังไม่เริ่มเขียนโค้ดหรือออกแบบภาพหน้าจอ
อ้างอิง: product-blueprint.md

## ขอบเขตที่ยืนยัน

- แพลตฟอร์มกลางรองรับหลายองค์กรผู้จัดงาน
- เริ่มวางแผน Dashboard ผู้จัดงานก่อน
- ผู้ใช้ขอให้ยังไม่ลงโค้ด
- ภาษาไทยและเงินบาทเป็นสมมติฐานเริ่มต้น ไม่ใช่ข้อกำหนดที่ยืนยันแล้ว

## เป้าหมาย

เมื่อเปิด Dashboard ผู้จัดต้องตอบได้ทันทีว่า งานไหนต้องดูแล ยอดสมัครเป็นอย่างไร เรื่องใดต้องทำก่อน และจะไปจัดการต่อได้ที่ไหน

แบ่งเป็นสองบริบท: ระดับองค์กรสำหรับดูหลายงาน และระดับงานสำหรับดำเนินการกับงานเดียว ต้องแสดงบริบทองค์กรและงานเสมอเพื่อป้องกันแก้ผิดงาน

## โครงสร้างเมนูที่เสนอ

### ระดับองค์กร

1. ภาพรวม: งานใกล้ถึงวันจัด ภารกิจค้าง และยอดสรุปที่มีขอบเขตชัดเจน
2. งานวิ่งของฉัน: รายการงาน ค้นหา กรองสถานะ สร้างงาน และทำสำเนางาน
3. การเงิน: ธุรกรรม เงินคืน และยอดนำส่งข้ามงาน สำหรับผู้มีสิทธิ์
4. ทีมงาน: สมาชิก บทบาท ขอบเขตงาน และคำเชิญ
5. ตั้งค่าองค์กรและสถานะการยืนยันผู้จัด: ข้อมูลองค์กร ที่อยู่ เอกสารยืนยันตัวตน/หนังสือมอบอำนาจ สถานะตรวจสอบผู้จัด (`DRAFT` / `SUBMITTED` / `UNDER_REVIEW` / `MORE_INFORMATION_REQUIRED` / `APPROVED` / `REJECTED` / `SUSPENDED`) และสถานะบัญชีรับเงิน โดยอนุญาตให้สร้างและเผยแพร่งานเปิดขายจริงเฉพาะองค์กรที่ผ่านการอนุมัติตามนโยบาย (ดูรายละเอียดขั้นตอนขึ้นทะเบียนผู้จัด 3 ขั้นตอนใน [Product blueprint ข้อ 16](product-blueprint.md))

ส่วนขยายที่เสนอ: ทางเข้าคำขอราคา/งานผลิตขององค์กร รวมรายการที่ไม่ผูกกับงานวิ่ง และภาพรวมคำสั่งซื้อสินค้าข้ามงานตามสิทธิ์

### ภายในงานที่เลือก

1. ภาพรวมงาน
2. ข้อมูลงานและหน้ารับสมัคร
3. ระยะ ราคา และโควตา
4. ผู้สมัคร
5. การเงินของงาน
6. BIB และการรับอุปกรณ์
7. การสื่อสาร
8. รายงาน
9. สิทธิ์และตั้งค่างาน

ส่วนขยายเมนูที่เสนอจากแผนสินค้า:

- **สินค้าและการขาย:** หน้าร้าน สินค้า/ไซซ์ ราคา สต็อก พรีออเดอร์ ลิงก์โปรโมท และคำสั่งซื้อจากนักวิ่ง/คนทั่วไป
- **จัดซื้อและผลิต:** คำขอราคา แบบ/ตัวอย่าง การอนุมัติ จำนวนและไซซ์ กำหนดผลิต ยอดชำระ และตรวจรับ
- ขยาย **BIB และการรับอุปกรณ์** เป็น **รับอุปกรณ์และจัดส่ง** พร้อมส่วน BIB เดิม แยกของตามสิทธิ์และซื้อเพิ่ม รวมการรับบางส่วน/จัดส่ง

ยังต้องทบทวนตำแหน่งเมนูและการรวมใน MVP ก่อนทำ wireframe รายละเอียด

เมนูที่ผู้ใช้ไม่มีสิทธิ์ให้ซ่อน แต่การป้องกันข้อมูลต้องตรวจที่ backend จริงในระยะพัฒนา ไม่ใช่อาศัยการซ่อนเมนู

## หน้าภาพรวมองค์กร

เรียงลำดับเนื้อหาตามการทำงาน:

1. บริบทองค์กร ตัวเลือกช่วงเวลา และปุ่มสร้างงาน
2. รายการที่ต้องดำเนินการ เช่น งานยังตั้งค่าไม่ครบ หรือมีรายการคืนเงินรอตรวจ โดยแสดงเฉพาะเรื่องที่ผู้ใช้จัดการได้
3. งานที่กำลังรับสมัครและงานใกล้วันจัด แต่ละงานแสดงวัน สถานะ จำนวนยืนยัน/โควตา และทางเข้าจัดการ
4. ตัวเลขรวมพร้อมคำจำกัดความ: ผู้สมัครยืนยัน ยอดชำระสำเร็จ เงินคืน และยอดนำส่งตามสิทธิ์
5. กิจกรรมล่าสุด เช่น เปลี่ยนโควตา ส่งออกข้อมูล หรือแก้ไขราคา พร้อมผู้ดำเนินการและเวลา

การกดตัวเลขต้องพาไปยังรายการต้นทางที่ใช้ตัวกรองเดียวกัน กราฟแนวโน้มเป็นข้อมูลประกอบ ไม่เบียดงานค้างและทางเข้าจัดการงาน

## หน้าภาพรวมงาน

- ชื่องาน วัน สถานที่ และสถานะ พร้อมดูหน้ารับสมัคร
- ก่อนเปิดขาย: checklist ความพร้อม ข้อมูลการแข่งขัน นโยบาย โควตา ราคา และบัญชีรับเงิน
- ระหว่างขาย: ยืนยัน/โควตา รอชำระ ยอดชำระ และรายการผิดปกติ
- ก่อนวันงาน: จำนวน BIB ที่ยังไม่กำหนด สรุปเสื้อ และความพร้อมรับอุปกรณ์
- วันรับอุปกรณ์: ทางลัดค้นหาหรือสแกน และจำนวนรับแล้ว/คงเหลือ
- หลังงาน: ผล/อัลบั้ม รายการเงินค้าง และรายงานปิดงาน

เน้นเนื้อหาตามช่วงชีวิตของงาน แต่เมนูหลักคงที่ ไม่เปลี่ยนตำแหน่งจนผู้ใช้หาไม่พบ

## นิยามตัวเลข

| ตัวเลข | ความหมาย | ข้อควรระวัง |
|---|---|---|
| ผู้สมัครยืนยัน | ผู้มีสิทธิ์เข้าร่วมตามสถานะใบสมัคร | ไม่ใช้จำนวนคำสั่งซื้อแทนจำนวนคน |
| รอชำระ | ใบสมัครที่ยังอยู่ในเวลารอจ่าย | ไม่รวมในผู้มีสิทธิ์ |
| โควตาว่าง | จำนวนรับลบสิทธิ์ยืนยันและการกันที่ยังไม่หมดอายุ | การกันโควตาไม่ใช่ยอดขาย |
| ยอดชำระสำเร็จ | ยอดรับเงินจริงตาม payment ที่สำเร็จในช่วงที่เลือก | แสดงก่อนหักคืนเงินและระบุฐานเวลา |
| เงินคืนสำเร็จ | เงินคืนที่ provider ยืนยันแล้ว | แยกคำขอคืนที่ยังไม่สำเร็จ |
| ยอดนำส่ง | ยอดตามรายการนำส่งให้ผู้จัด | ไม่เท่ากับยอดชำระหรือรายได้แพลตฟอร์ม |
| รับอุปกรณ์แล้ว | ผู้เข้าร่วมที่มีรายการส่งมอบสำเร็จ | ไม่เท่ากับมาแข่งหรือวิ่งจบ |

ตัวเลขตลอดอายุงานและตัวเลขตามช่วงเวลาไม่วางรวมกันโดยไม่มีป้ายบอก แยกวันที่สมัคร วันที่ชำระ และวันที่คืนเงินในรายงาน และแสดงเวลาที่ข้อมูลอัปเดตล่าสุด

## หน้าผู้สมัคร

ตารางหลัก: รหัสใบสมัคร ชื่อผู้เข้าร่วม ประเภทวิ่ง สถานะสิทธิ์ สถานะชำระ BIB และสถานะรับอุปกรณ์

- ค้นหาด้วยชื่อ รหัสใบสมัคร หรือ BIB ตามสิทธิ์
- กรองประเภท สถานะ และช่วงเวลา
- เปิดรายละเอียดพร้อมประวัติ แสดงข้อมูลติดต่อเฉพาะบทบาทที่จำเป็น
- แก้ช่องที่นโยบายอนุญาต โดยเก็บผู้แก้และค่าก่อน/หลัง
- ส่งออกข้อมูลตามตัวกรอง พร้อมระบุจำนวนและขอบเขตก่อนดาวน์โหลด
- การคืนเงินและยกเลิกสิทธิ์มี workflow แยก ไม่ใช้ปุ่มลบใบสมัคร

## การสร้างงาน

ข้อมูลงาน → ประเภทการแข่งขัน → ราคา/โควตา/เสื้อ → ข้อมูลที่ต้องเก็บและเงื่อนไข → ตรวจหน้ารับสมัคร → ส่งตรวจเผยแพร่

บันทึกแบบร่างได้ระหว่างทาง ระบุส่วนที่ไม่ครบและพากลับไปแก้ เผยแพร่ได้เมื่อผ่านกติกาของแพลตฟอร์ม

## สิทธิ์ที่เกี่ยวข้อง

### การเข้าสู่ Dashboard และบัญชีส่วนบุคคล

เพิ่มแผนวันที่ 17 พฤศจิกายน 2026: รองรับอีเมล/รหัสผ่าน Google และ LINE ในบัญชีเดียว รายละเอียดหลักอยู่ใน [Product blueprint ข้อ 16](product-blueprint.md) ยังไม่ใช่ระบบ Login จริงของต้นแบบ

- มีหน้า Login/Register, ยืนยันอีเมล, ลืม/รีเซ็ตรหัสผ่าน และการตั้งค่าผู้ใช้ใหม่
- รองรับ LINE ไม่มีอีเมล เพิ่มและยืนยันช่องทางติดต่อเมื่อจำเป็น
- เพิ่ม “บัญชีและความปลอดภัย” ในเมนูผู้ใช้ แยกจากตั้งค่าองค์กร: อีเมล รหัสผ่าน บัญชีที่เชื่อม และ session อุปกรณ์
- กลับไปหน้าที่เริ่มทำรายการหรือเลือกองค์กรตาม membership ที่ยังใช้ได้ ไม่ให้สิทธิ์จากการเลือกบทบาทสาธิต
- คำเชิญเข้าทีมและสมัครเป็นผู้จัดใช้บัญชีเดิม แต่ตรวจสิทธิ์และเงื่อนไขแยก
- วางหน้าจอผิดรหัส ลิงก์หมดอายุ provider ยกเลิก ไม่มีสิทธิ์องค์กร และบัญชีเชื่อมกับผู้ใช้อื่น ห้ามรวมบัญชีอัตโนมัติจากอีเมลตรงกัน

### บทบาทภายในองค์กร

| บทบาท | การเข้าถึงหลัก |
|---|---|
| เจ้าขององค์กร | งาน ทีม ข้อมูลองค์กร และการเงินตามข้อตกลง |
| ผู้จัดการงาน | งานที่ได้รับมอบหมายและข้อมูลผู้สมัครที่จำเป็น |
| ฝ่ายการเงิน | ธุรกรรม รายงาน คำขอคืน และรายการนำส่ง |
| เจ้าหน้าที่รับอุปกรณ์ | ค้นหาสิทธิ์ BIB เสื้อ และยืนยันส่งมอบเฉพาะงาน |

ผู้จัดการงานไม่ควรได้สิทธิ์เปลี่ยนบัญชีรับเงินโดยอัตโนมัติ ผู้ดูแลแพลตฟอร์มเป็นอีกบริบทหนึ่ง ไม่ปะปนกับ Dashboard ผู้จัด

## สถานะหน้าจอที่ต้องวางแผน

- องค์กรใหม่ไม่มีงาน: ขั้นตอนเริ่มต้นและปุ่มสร้างงาน
- งานแบบร่าง: checklist และบันทึกต่อ
- ไม่มีผลค้นหา: แสดงตัวกรองและทางล้างตัวกรอง
- ข้อมูลกำลังโหลด: รักษาโครงหน้าและไม่แสดงศูนย์ปลอม
- โหลดผิดพลาด: ระบุส่วนที่ผิดพลาดและให้ลองใหม่ โดยส่วนอื่นยังทำงานได้
- ไม่มีสิทธิ์: อธิบายการติดต่อเจ้าขององค์กรโดยไม่เปิดเผยข้อมูลต้องห้าม
- ทำรายการสำเร็จ/ล้มเหลว: แจ้งผลที่ยืนยันแล้ว ไม่รายงานสำเร็จจากการกดปุ่มอย่างเดียว
- งานระงับ/ยกเลิก: แสดงเหตุผลและขั้นตอนถัดไป แต่ยังเข้าถึงหลักฐานตามสิทธิ์

## ลำดับออกแบบ

### ชุดแรก: โครงหลัก

ภาพรวมองค์กร → รายการงาน → ภาพรวมงาน → รายการผู้สมัครและรายละเอียด

เป้าหมาย: ตรวจว่าเมนู บริบท และข้อมูลตอบโจทย์การทำงานจริงก่อน

### ชุดที่สอง: ตั้งค่างาน

สร้างงาน → ประเภท/ราคา/โควตา → checklist → พรีวิว/ส่งตรวจ

### ชุดที่สาม: ปฏิบัติการ

การเงิน → BIB/รับอุปกรณ์ → ส่งออก → ทีมและสิทธิ์ → การสื่อสาร

เป็นลำดับออกแบบ ไม่ใช่ข้อเสนอให้เปิดขายจริงก่อนระบบเงินและสิทธิ์พร้อม

## ส่วนขยาย: ร้านค้าและบริการผลิต

อ้างอิงกฎธุรกิจหลักใน [Product blueprint ข้อ 15](product-blueprint.md) การเพิ่มแผนไม่ใช่การอนุญาตให้เริ่มพัฒนา

### จุดชวนผู้จัดใช้บริการผลิต

- สร้างงาน: เลือกต้องการความช่วยเหลือผลิตเสื้อ/เหรียญ
- เพิ่มสินค้า: เลือกสินค้าของตน ขอผลิต หรือบริการครบตามข้อตกลง
- รายงานไซซ์: ขอราคาจากยอดที่ตรวจสอบแล้ว แยกสิทธิ์แพ็กเกจ ซื้อเพิ่ม สำรอง และสินค้าที่มี ไม่รวมซ้ำ
- ก่อนปิดผลิต: แจ้งวันปิดยอด รออนุมัติแบบ/ราคา และความเสี่ยงต่อกำหนดส่ง
- ทำงานปีถัดไป: ใช้แบบและยอดรวมเดิมช่วยประมาณการ

### หน้าจอและข้อมูลที่เสนอ

| หน้า | ข้อมูลและการทำงาน |
|---|---|
| หน้าร้าน/โปรโมท | พรีวิวร้าน ภาพและรายละเอียดสินค้า ลิงก์แชร์ ผู้ขาย และเงื่อนไข |
| สินค้า | SKU/ไซซ์ พร้อมขายหรือพรีออเดอร์ ราคา คงเหลือ/เพดาน วันปิดและคาดส่ง |
| คำสั่งซื้อ | ผู้ซื้อ รายการ จำนวน สถานะจ่าย/คืน รับหน้างาน/จัดส่ง และใบสมัครถ้ามี |
| ขอราคา | แบบ วัสดุ จำนวนแยกไซซ์ วันต้องการรับ และข้อมูลติดต่อ |
| งานผลิต | ใบเสนอราคา เวอร์ชันแบบ การอนุมัติ มัดจำ/ยอดคงเหลือถ้ามี สถานะผลิต/ตรวจรับ |
| ส่งมอบ | ของตามสิทธิ์และซื้อเพิ่ม แยกรายการ/จำนวน รับบางส่วน และหมายเลขติดตาม |

หน้าร้านของงานเข้าถึงลูกค้าทั่วไปได้โดยไม่บังคับสมัครวิ่ง และต้องวางเส้นทางซื้อแยกจากแบบฟอร์มสมัคร ส่วนงานสั่งทำของทีม/บริษัทอาจไม่มี event จึงห้ามบังคับสร้างงานวิ่งเพื่อขอราคา

### สิทธิ์และกรณีผิดปกติ

- สิทธิ์จัดการสินค้า อนุมัติจัดซื้อ อนุมัติแบบ และคืนเงินต้องกำหนดแยก ไม่ให้เจ้าหน้าที่รับของอนุมัติเงินหรือผลิตได้อัตโนมัติ
- แสดงกรณีสินค้าหมด พรีออเดอร์ไม่ถึงขั้นต่ำ ใบเสนอราคาหมดอายุ แบบต้องแก้ ผลิตล่าช้า ส่งไม่ครบ ชำรุด และคืนเงินไม่สำเร็จ
- ตัวเลขแยกยอดขายสินค้า ยอดคำขอราคา ยอดสั่งผลิต และยอดส่งมอบ ไม่ใช้ยอดสนใจแทนยอดชำระ
- การยกเลิกงานกับการยกเลิกสินค้า/ผลิตเป็นคนละการตัดสินใจ ต้องแสดงนโยบายที่ใช้

### ขอบเขตเริ่มต้นที่เสนอ

หน้าร้านเฉพาะงาน พรีออเดอร์ ซื้อเพิ่ม และแบบฟอร์มขอราคา โดยทีมจัดการประสานโรงงานหลังบ้านก่อน ยังไม่ทำ marketplace ผู้ผลิตหรือระบบโรงงานอัตโนมัติ

## สิ่งที่ยังไม่ทำ (ขอบเขตคงเดิม)

- ยังไม่เลือก framework หรือเขียนโค้ด
- ยังไม่ล็อกสี ฟอนต์ หรือรูปแบบภาพสุดท้าย
- ยังไม่ใส่สถิติหรือข้อมูลผู้จัดจริงที่ไม่มีแหล่งข้อมูล
- ยังไม่ทำตลาดภาพถ่าย Virtual Run หรือ timing สดใน Dashboard รุ่นแรก

## เกณฑ์ทบทวน wireframe

- ผู้จัดบอกได้ว่ากำลังอยู่ในองค์กรและงานใด
- หาเรื่องเร่งด่วนและเข้ารายการต้นทางได้โดยไม่ไล่หลายเมนู
- แยกผู้สมัคร ยอดชำระ และยอดนำส่งได้ชัดเจน
- จัดการตั้งแต่งานว่าง แบบร่าง เปิดขาย จนปิดงานได้
- เจ้าหน้าที่รับอุปกรณ์ใช้มือถือได้โดยไม่ต้องเลื่อนตารางกว้าง
- งานสำคัญไม่อาศัยสีอย่างเดียว และใช้งานด้วยคีย์บอร์ดได้

## เรื่องที่ต้องยืนยันต่อ

1. งานประเภทแรกที่รองรับ: งานถนนทั่วไป หรือมี trail/หลายวัน/relay ตั้งแต่เริ่ม
2. บทบาทที่ผู้จัดใช้งานบ่อยที่สุด และต้องรับอุปกรณ์ผ่านมือถือในรุ่นแรกหรือไม่
3. กติกาเผยแพร่ ค่าบริการ คืนเงิน และนำส่งเงินก่อนออกแบบหน้าการเงินละเอียด

## อัปเดตสถานะการพัฒนาต้นแบบ (18 พฤศจิกายน 2026)

- **แยก 2 ระดับของ Dashboard ผู้จัดงานชัดเจน (`OrganizerDashboardView.tsx` + `OrganizerAnalyticsCharts.tsx`):**
  1. **Organization Overview (`ดูภาพรวมทุกงานขององค์กร`)**: แสดงคิวงานด่วน (`Action Queue`), แถบสมการโควตาและเงินรวมทุกงาน (`BibLedgerStrip`), และชุดกราฟวิเคราะห์ครบ 10 Components แยกตาม Priority (`P1 KPI Cards`, `P1 Registration Trend`, `P1 Registration Status`, `P1 Revenue Trend`, `P1 Upcoming Events`, `P2 Distance Breakdown`, `P2 Event Performance`, `P2 Capacity`, `P3 Demographics`, `P3 Payment Method`) พร้อมปุ่มเข้าสู่ Event Dashboard รายงาน
  2. **Event Dashboard (`เจาะลึกงานวิ่งแต่ละงาน`)**: มีแถบสลับหมวดเจาะลึก 6 ด้าน (`ภาพรวม & กราฟเจาะลึก`, `โควตา & คำถามสมัคร`, `นักวิ่ง`, `การชำระเงิน & คืนเงิน`, `Check-in & จ่าย BIB`, `ร้านค้าของที่ระลึก`) พร้อมแผง `Event Deep-Dive` แสดงหลอดความคืบหน้า Check-in หน้างานคู่กับสถานะการชำระเงินของงานนั้น
- **การตั้งค่าฟอร์มรับสมัครและส่งคำขอหา Platform Owner (`Organizer Form Customizer & Field Request`):**
  - ย้ายการสร้าง/แก้ไขโครงสร้างฟิลด์และลำดับขั้นตอนการสมัคร (`Steps`) ไปที่ศูนย์ควบคุมของ **Platform Owner (`Registration Form Builder` ใน `/platform-admin`)**
  - ผู้จัดงานเลือกแม่แบบมาตรฐาน (`Fun Run`, `Mini Marathon`, `Half Marathon`, `Marathon / Trail`, `Custom Template`), ปรับแต่งเฉพาะฟิลด์ที่ได้รับสิทธิ์ (`LOCKED` / `CONFIGURABLE` / `CUSTOMIZABLE`) และ **ส่งคำขอ (Request) ผ่านแพลตฟอร์ม** เมื่อต้องการให้นักวิ่งกรอกข้อมูลเพิ่มเติม (รายละเอียดใน [docs/product-blueprint.md ข้อ 17](product-blueprint.md))
