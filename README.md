# RunEvent

แพลตฟอร์มกลางสำหรับหลายผู้จัดงานวิ่ง (Multi-Tenant B2B2C) เชื่อมการสร้างงาน รับสมัคร ชำระเงิน จัดการนักวิ่ง และการรับอุปกรณ์ โดยนำแนวคิดการบริหารงานและค่าบริการตามการสมัครจาก **RunSignup** และประสบการณ์ค้นหางานวิ่ง/บริการอัลบั้มหลังงานจาก **ThaiRun** มาปรับใช้กับผลิตภัณฑ์ของเราโดยไม่คัดลอกแบรนด์หรือหน้าจอ

## สถานะโปรเจกต์

**มีต้นแบบโต้ตอบบนเครื่องผู้ใช้แล้ว (Interactive Local Mockup v2 — อัปเดตเมื่อ 17 พฤศจิกายน 2026)**

- **สิ่งที่พัฒนาแล้วในระดับต้นแบบฝั่งหน้าบ้าน (Client-Side Mockup):**
  - เว็บต้นแบบ `Vite + React + TypeScript` รันบน Local ครอบคลุมทั้งฝั่งลูกค้าทั่วไป/นักวิ่ง ระบบบัญชีจำลอง และฝั่งผู้จัดงาน:
    1. **หน้าค้นหางานวิ่งและร้านค้าสไตล์ Modern Minimal (`CustomerPortalView`):** ค้นหาและกรองงานวิ่ง ดูราคาสุทธิตามนโยบายค่าบริการ (`runner_pays` / `organizer_absorbs` / `split_50_50`), สมัครวิ่งเป็นลำดับ 3 ขั้นตอนพร้อมเลือกซื้อของที่ระลึกเพิ่ม, **ร้านค้าเฉพาะงานสำหรับลูกค้าทั่วไป** ซื้อเสื้อ/เหรียญหรือพรีออเดอร์โดยไม่เกิดใบสมัครวิ่ง, หน้าขอใบเสนอราคาสั่งผลิตเสื้อ/เหรียญสำหรับชมรมหรือบริษัทที่ไม่มีงานวิ่ง, ดูอัลบั้มภาพหลังงาน และหน้า “ตั๋ววิ่งและคำสั่งซื้อของฉัน” ที่แยกใบสมัครวิ่งออกจากคำสั่งซื้อสินค้า
    2. **ระบบเข้าสู่ระบบจำลอง Email / Google / LINE, URL Routing รายหน้า และเมนูตามสิทธิ์จริง (`AuthViews` + `App`):** เริ่มต้นแบบผู้เยี่ยมชมทั่วไป (`Guest`), ผูก URL จริง (`/`, `/events/:code`, `/events/:code/shop`, `/custom-production`, `/my-orders`, `/login`, `/account/security`, `/organizer`), ซ่อนปุ่ม `ระบบผู้จัดงาน` บนแถบบนเมื่อเป็นลูกค้าทั่วไปที่ไม่มี `OrganizationMembership`, กั้นหน้า `/organizer` ด้วย Route Guard (`403` สำหรับลูกค้าทั่วไป) และย้ายตัวสลับบัญชีสาธิต 6 บทบาทไปไว้ในปุ่มลอยพับเก็บได้มุมขวาล่าง (`Dev / Demo`) เพื่อไม่ปะปนกับหน้าจอผู้ใช้จริง
    3. **Organizer Dashboard ที่อธิบายหน้าที่ทุกส่วนชัดเจน (`OrganizerDashboardView` + `BibLedgerStrip`):** แยกบริบทระดับองค์กรกับระดับงานวิ่ง พร้อมคำอธิบายทุกหน้าว่าคืออะไรและใช้ทำอะไร, คิวงานด่วน, แถบสถานะความพร้อม 4 ช่วงของงาน, แถบสมการโควตาและยอดนำส่งสุทธิ (แยกยอดขายสินค้าร้านค้าต่างหาก), สร้างงานแบบร่างและทำสำเนางานโดยไม่คัดลอก PII, จัดการร้านค้าเฉพาะงานและคำนวณยอดสั่งผลิตเสื้อไม่ซ้ำ (`สิทธิ์แพ็กเกจ + ร้านค้า + สำรอง − สต็อกเดิม`), จัดการผู้สมัคร/คืนเงิน และจุดเช็กอินบนมือถือที่แยกการรับ BIB นักวิ่งออกจากการส่งมอบสินค้าร้านค้า (รับบางส่วน/รับครบ)
  - **Workspace Skill สำหรับรันบน Local:** `.agents/skills/run-local/SKILL.md` พร้อมสคริปต์ช่วยรันและตรวจ build
- **ข้อจำกัดสำคัญของต้นแบบ (Persistence & Truthfulness):**
  - ข้อมูลทั้งหมดเป็น **ข้อมูลสาธิตสมมติ (Synthetic Demo Data)** เก็บสถานะไว้ในหน่วยความจำและ `localStorage` ของเบราว์เซอร์ (`runevent_v2_mock_system`) เท่านั้น
  - **ยังไม่มีเซิร์ฟเวอร์ Backend จริง, ยังไม่มีฐานข้อมูลจริง, ยังไม่ได้เชื่อมต่อ Google/LINE OAuth จริง, ยังไม่มีการส่งอีเมลจริง, ยังไม่มีการตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ และไม่มีการรับชำระเงินจริง** อัตราค่าบริการ (`5% + ฿15`) และต้นทุนผลิตประเมินในต้นแบบเป็นตัวเลขสมมติเพื่อสาธิตกลไกการคำนวณเท่านั้น

## วิธีรันโปรเจกต์ต้นแบบบน Local

ต้องมี **Node.js (>= 18)** และ **npm** ติดตั้งในเครื่อง

### รันด้วยคำสั่ง npm มาตรฐาน

```bash
npm install
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:5173/` (หรือพอร์ตที่ Vite แสดงในเทอร์มินัล)

### คำสั่งตรวจสอบความถูกต้อง (Typecheck & Build)

```bash
npm run typecheck
npm run build
```

### รันผ่านสคริปต์ของ Workspace Skill (`run-local`)

- **Windows PowerShell:**
  ```powershell
  powershell -ExecutionPolicy Bypass -File .\.agents\skills\run-local\scripts\start-local.ps1
  ```
- **macOS / Linux / Git Bash:**
  ```bash
  sh ./.agents/skills/run-local/scripts/start-local.sh
  ```

## ฟีเจอร์บัญชีและการเข้าสู่ระบบ — แผนที่เพิ่ม 17 พฤศจิกายน 2026

ผู้ใช้ยืนยันให้รองรับ **อีเมล + รหัสผ่าน, Google และ LINE** โดยใช้บัญชี RunEvent เดียวกัน ต้นแบบปัจจุบันจำลองหน้าจอและสถานะใน `localStorage` เพื่อทบทวน UX เท่านั้น **ยังไม่ได้พัฒนาเป็นระบบยืนยันตัวตนฝั่งเซิร์ฟเวอร์จริง** และการจำลอง OAuth/สลับบัญชีสาธิตในต้นแบบไม่ใช่ Google/LINE Login หรือระบบรหัสผ่านจริง

- สมัครด้วยอีเมล ยืนยันอีเมล เข้าสู่ระบบ ลืมรหัสผ่าน และรีเซ็ตรหัสผ่าน
- Google/LINE ใช้ทางเข้าร่วมสำหรับผู้ใช้ใหม่และผู้ใช้เดิม ผู้ใช้ใหม่ตั้งค่าบัญชีเพิ่มเติมเท่าที่จำเป็น
- รองรับ LINE ที่ไม่มีอีเมล โดยให้เพิ่มและยืนยันช่องทางติดต่อเมื่อจำเป็น
- เชื่อม Google/LINE หรือเพิ่มรหัสผ่านให้บัญชีเดิมหลังยืนยันตัวตน ไม่รวมบัญชีจากอีเมลตรงกันโดยอัตโนมัติ
- หน้า “บัญชีและความปลอดภัย” สำหรับอีเมล รหัสผ่าน วิธีเข้าสู่ระบบที่เชื่อม และออกจากระบบอุปกรณ์อื่น
- หลัง Login กลับไปสมัคร/ซื้อสินค้าต่อ หรือเลือกองค์กรตามสิทธิ์จริง บัญชีหนึ่งเป็นทั้งนักวิ่ง ลูกค้า และสมาชิกหลายองค์กรได้
- สมัครเป็นผู้จัดหรือรับคำเชิญเข้าทีมแยกจากการ Login ไม่ให้สิทธิ์ผู้จัดจากการเลือกบทบาทเอง

รายละเอียด flow ข้อมูล และเกณฑ์ทดสอบอยู่ใน [Product blueprint ข้อ 16](docs/product-blueprint.md) การเพิ่มฟีเจอร์ในเอกสารไม่ใช่การอนุญาตให้เชื่อม backend หรือผู้ให้บริการจริงในงานนี้

## ผู้ใช้งานที่จำลองในต้นแบบ (ปัจจุบัน)

| กลุ่ม | งานหลัก |
|---|---|
| นักวิ่ง | ค้นหางาน ดูราคาสุทธิ สมัครจำลอง ดูสิทธิ์/QR รับอุปกรณ์ แก้ไซส์เสื้อก่อนเส้นตาย และเปิดลิงก์อัลบั้มภาพหลังงาน |
| เจ้าขององค์กร | สลับหลายองค์กร บริหารงาน ทีม ตั้งค่าผู้รับภาระค่าบริการ และดูสมการยอดนำส่ง |
| ผู้จัดการงาน | ตั้งค่างานและจัดการผู้สมัครเฉพาะงานที่รับผิดชอบ (ไม่มีสิทธิ์ดูการเงินรวมหรือแก้บัญชีธนาคาร) |
| ฝ่ายการเงิน | ตรวจธุรกรรม อนุมัติ/ปฏิเสธคำขอคืนเงิน และตรวจรอบนำส่ง |
| เจ้าหน้าที่รับอุปกรณ์ | ค้นหาสิทธิ์/QR Token กำหนดเลข BIB ไม่ซ้ำ และบันทึกการส่งมอบเสื้อ+BIB บนมือถือ |
